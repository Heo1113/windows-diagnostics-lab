# Windows Diagnostics Lab 사용 설명서

이 프로그램은 Windows가 이미 남기고 있는 기록(이벤트 로그, 충돌 기록, 구성 정보)과 실행 중에 기록한 센서 값을 모아
**언제 무슨 일이 있었고 그 전후에 무엇이 바뀌었는지**를 보여 줍니다. 원인을 단정하지 않습니다. 화면의 모든 결과는 세 가지로 구분됩니다.

| 구분 | 뜻 | 예 |
|---|---|---|
| 확인된 사실 | Windows 기록에 실제로 적힌 내용 | "11월 1일 22:14에 BugCheck 0x116이 기록됨" |
| 관측된 연관성 | 시간·통계로 본 관계. 원인이라는 뜻이 아님 | "드라이버 변경 뒤 GPU 오류가 하루 0.1회 → 1.2회로 늘어남 (p=0.003)" |
| 원인 후보 (추가 검증 필요) | 지식 규칙에 따른 조사 방향과 검증 방법 | "GPU 드라이버 또는 GPU 안정성 — 근거 강도: 보통" |

> 이 프로그램은 설정을 바꾸지 않습니다. BIOS·전압·클럭 변경, 드라이버 설치·제거, 레지스트리 수정, 업데이트 제거, 이벤트 로그 삭제를 하지 않으며,
> 그런 조치를 자동으로 실행하는 버튼도 없습니다. 조치는 사용자가 판단해 직접 하고, 그 변경을 이 프로그램에 '변경 기록'으로 남겨 전후를 비교하세요.

## 1. 처음 실행

1. `WindowsDiagnosticsLab.exe`를 실행합니다. 관리자 권한으로 실행할 필요가 없습니다.
2. 처음에는 과거 30일(설정에서 변경)의 이벤트를 가져옵니다. 로그가 많으면 수십 초 걸립니다. 하단 상태 줄에 진행 상태가 보입니다.
3. 구성 스냅샷(Windows 빌드, BIOS, 메모리 모듈, GPU 드라이버, 장치 드라이버 목록)을 저장하고 센서 기록을 시작합니다.
4. 창을 닫으면 프로그램이 끝나고 수집도 멈춥니다. 꺼져 있던 동안의 이벤트는 다음 실행 때 Windows 로그에서 이어서 가져오지만,
   **센서 값은 실행 중일 때만 기록**됩니다.

화면 위쪽에 노란 띠가 보이면 읽어 보세요.

- `MOCK 센서`: 테스트용 가상 센서 값입니다(`--mock-sensors`로 실행한 경우).
- `가상 데이터 포함`: 설정 화면에서 가상 시나리오를 불러온 경우입니다. 가상 이벤트는 제목이 `[가상]`으로 시작하고, 분석 결과에도 포함 사실이 표시됩니다.
- `이전 실행이 정상 종료되지 않았습니다`: 지난번에 프로그램이 강제 종료되었거나 PC가 멈춘 경우입니다. 마지막 기록까지의 데이터는 보존되어 있습니다.

## 2. 화면별 설명

### 대시보드

- **상태 요약**: 최근 24시간·7일의 심각·오류·경고 수와 전체 상태.
- **새 경고·오류**: '모두 확인함'을 누른 뒤 새로 수집된 경고 이상 이벤트. '모두 확인함'은 기록을 지우지 않고 기준점만 옮깁니다.
- **중요 경고 (최근 7일)**: 시스템 충돌, WHEA 하드웨어 오류, GPU 드라이버 오류, 프로그램 충돌, 디스크 오류, 서비스 오류를 종류별로 묶어 표시.
- **GPU·CPU·RAM 현재 값**: 프로젝트 A의 센서 모듈이 읽은 실측값. 읽을 수 없는 값은 `N/A`입니다(0이나 추정값을 넣지 않음).
- **30일 오류 추이**, **최근 시스템 충돌**(누르면 진단 화면의 충돌 상세로 이동), **로그별 수집 상태**(정상·권한 부족·로그 없음·꺼짐 등).

### 이벤트 탐색

- 검색어(제목·메시지·공급자, 숫자를 넣으면 이벤트 ID), 기간, 중요도, 로그, 공급자, 분류로 거릅니다.
  '마지막 확인 이후 새 이벤트만'으로 새 기록만 볼 수 있습니다.
- **같은 문제끼리 묶어 보기**: 같은 공급자·이벤트 ID·서명(프로그램/모듈/예외 코드, 서비스 이름, 장치 등)을 한 줄로 묶어 횟수·일수·처음·마지막을 보여 줍니다.
  '목록'을 누르면 그 유형의 이벤트만 봅니다.
- **상세**: 의미, **이 이벤트만으로 알 수 없는 것**(예: Kernel-Power 41은 전원 공급 장치 고장을 뜻하지 않음), 이벤트에서 읽은 값,
  메시지(개인정보 가림), 원본 이벤트 데이터. '전후 센서 보기'와 '타임라인에서 보기'로 같은 시각의 다른 기록을 확인합니다.
- **메모**: 같은 유형의 이벤트 전체에 붙는 메모입니다. 조사한 내용을 남겨 두세요.
- **CSV/JSON 내보내기**: 기본은 '개인정보 최소'(메시지·이벤트 데이터 제외). 확인 창에서 '예'를 고르면 메시지를 포함한 상세 내보내기가 되며, 이때도 이름·경로는 가립니다.

### 하드웨어

- **현재 값**과 GPU 전력·온도·사용률·클럭, CPU 사용률, RAM 사용 비율 그래프. 기간은 실시간(60분)~30일.
- 그래프의 **세로선**은 그 시각의 경고 이상 이벤트입니다(빨강: 오류 이상, 노랑: 경고).
- 그래프 위에서 마우스 휠은 화면을 스크롤합니다. 시간축 확대·축소는 **Ctrl+휠**, 이동은 끌기입니다.
  표·목록 위에서는 표가 먼저 스크롤되고, 표의 끝에 닿으면 화면이 이어서 스크롤됩니다.
- 다른 화면에서 '전후 센서 보기'로 오면 그 이벤트 전후(기본 ±10분)를 보여 주고 이전/이후 평균·최대를 표로 비교합니다.
  그 시각에 프로그램이 실행 중이 아니었다면 "센서 기록 없음"이라고 표시합니다.
- **센서 지원 현황**: 센서별로 읽을 수 있는지, 관리자 권한이 필요한지. CPU 온도·CPU 전력은 커널 드라이버와 관리자 권한이 필요해 이 버전에서 수집하지 않습니다.
  메모리 전압도 실측하지 않습니다(메모리 모듈의 SMBIOS 보고값만 구성 정보에 표시).
- 센서 값과 이벤트가 같은 시각에 있다는 것은 **시간적 관계일 뿐** 원인을 뜻하지 않습니다.

### 타임라인

- 날짜별로 시스템 변경(업데이트·드라이버 설치), 오류, 프로그램 충돌, 시스템 충돌, 시작·종료, 하드웨어 관측(센서 기록 구간·수집 누락), 사용자 기록을 시간 순으로 보여 줍니다.
  항목마다 출처(Windows 이벤트 로그, 구성 스냅샷 비교, 사용자 입력 등)가 표시됩니다.
- 구성 스냅샷으로 알아낸 변경은 정확한 시각을 알 수 없으므로 "이전 스냅샷 ~ 이번 스냅샷 사이"로 표시합니다.
- **변경 기록 추가 (사용자 입력)**: BIOS 업데이트·BIOS 설정·EXPO·메모리 전압·GPU 드라이버·GPU 설정·Windows 업데이트·하드웨어 교체 등
  프로그램이 읽을 수 없는 변경을 직접 기록합니다. '바뀐 값'에 이름/이전/이후/단위(예: VDD 1.35 → 1.40 V)를 넣을 수 있습니다.
  이 값은 항상 **사용자 입력**으로 표시되어 실측값과 섞이지 않습니다.
- 선택한 항목으로 상세 열기, 전후 센서, **기준선으로 지정**, 사용자 기록 삭제(확인 후, 사용자가 만든 기록만)를 할 수 있습니다.

### 진단

- '분석 실행'으로 선택한 기간(기본 30일)의 보고서를 만듭니다.
- **원인 후보 (검증 필요)**: 근거 강도(강함·보통·약함), 근거 목록, **추가 검증 방법**, 주의 사항. '관련 이벤트 열기'로 근거 이벤트를 봅니다.
- **관측된 연관성**: 변경 시점 전후의 빈도 변화, 무작위로 기대되는 것보다 자주 함께 기록되는 이벤트, 충돌 직전에 반복된 기록, 고부하·고온 경향.
- **확인된 사실**: 기록 수, 충돌 횟수, 수집 범위.
- **시스템 충돌**: 다음 부팅 때 기록되는 Kernel-Power 41, EventLog 6008, BugCheck 1001, WHEA 치명 오류, 덤프 파일을 한 사건으로 묶어
  BugCheck 코드·매개변수, 충돌 시각의 근거(덤프 헤더·6008·알 수 없음), 마지막으로 정상 기록된 시각, 직전 30분의 기록, 직전 센서 값을 보여 줍니다.
- **반복 문제**, **수집 범위와 한계**(읽지 못한 로그, 누락 구간, 센서 기록 시간).
- **보고서 HTML/Markdown**, **진단 자료 묶음**(보고서 + 이벤트·타임라인·센서 CSV + 구성 JSON).

### 비교

- **기준선**: BIOS 업데이트, GPU 드라이버 교체, EXPO 적용, 메모리 전압 변경, Windows 업데이트처럼 비교하고 싶은 시점. 직접 입력,
  '지금을 기준선으로', 타임라인의 사용자 기록에서 만들 수 있습니다.
- **전후 비교**: 기준선 이전 N일과 이후 N일(3~90일)을 비교합니다.
  - 분류별 하루당 빈도와 정확 검정 p값, 판단('우연으로 보기 어려운 차이 (p<0.01 또는 p<0.05)', '우연으로도 설명 가능한 차이',
    '표본이 적어 판단 어려움'). 한 번의 충돌이 남기는 여러 기록은 한 번으로 셉니다.
  - 이후에 새로 나타난 문제, 사라진 문제.
  - 센서 통계(프로그램 실행 중 기록분만), 구성 차이(기준선 시점과 이후 구간 끝의 스냅샷).
  - **같은 기간의 다른 변경**: 비교 기간 안에 다른 변경이 있었다면 그것도 영향을 줬을 수 있으므로 함께 표시합니다.
- 이전 구간 일부에 이벤트 기록이 없으면(프로그램 설치 전이고 Windows에도 남아 있지 않은 기간) 기록이 있는 기간만으로 비교하고 그 사실을 메모로 표시합니다.
  센서 기록이나 구성 스냅샷이 없는 경우에도 값을 만들어 내지 않고 "없다"고 표시합니다.
- **결과 저장**, HTML/CSV/JSON 내보내기, **구성 스냅샷 직접 비교**(두 스냅샷을 골라 차이 표시).

### 설정

| 묶음 | 내용 |
|---|---|
| 수집 대상 | 로그 목록(기본: System, Application, Setup, Kernel-PnP/Configuration. WindowsUpdateClient/Operational은 추가 가능), 과거 기간, 확인 간격, 제외 공급자 |
| 과거 로그 가져오기 | 프로그램 설치 이전의 기록을 원하는 기간만큼. 이미 저장된 이벤트는 다시 저장하지 않음. Windows에 남아 있는 기간까지만 가능 |
| 구성 스냅샷·덤프 | 스냅샷 간격, 장치 드라이버 목록 포함, 지금 스냅샷, 덤프 파일 확인 |
| 센서 | 기록 사용, GPU(NVML)·CPU/RAM 센서, 기록 간격 |
| 데이터 보존 | 이벤트 보존(기본 무기한), 센서 보존(기본 30일), DB 크기 경고 기준. 보존 정책 적용은 확인 후 오래된 행만 지움. DB 파일은 지우지 않음 |
| 알림 | 화면 알림, 알림 영역 풍선, 최소 중요도, 같은 문제 반복 알림 묶음 시간 |
| 개인정보 | 수집 시 마스킹(권장), UTC 표시 |
| 분석 | 동시 발생 간격, 이벤트 전후 센서 구간, 반복 문제 최소 횟수, GPU 고온 기준 |
| 데이터·백업 | 백업, 백업 검증, 백업에서 복원(확인 후, 현재 DB는 옆에 보관하고 재시작), 무결성 검사, 데이터·로그 폴더 열기 |
| 테스트용 | 가상 시나리오 불러오기(확인 후). 화면 확인용이며 `[가상]`으로 표시됨 |

'저장'을 눌러야 설정이 적용됩니다. '되돌리기'는 저장하지 않은 변경을 취소합니다.

## 3. 작업 흐름

### 블루스크린(BSOD)이나 갑작스러운 재부팅을 조사할 때

1. 대시보드의 **최근 시스템 충돌**에서 해당 항목을 누르거나, 진단 화면의 **시스템 충돌** 표에서 고릅니다.
2. 충돌 상세에서 확인합니다.
   - BugCheck 코드와 이름(예: `0x116 VIDEO_TDR_FAILURE`). 코드 설명은 일반적인 의미이며 원인 장치를 확정하지 않습니다.
   - 충돌 시각의 근거: 덤프 헤더 시각이면 정확도가 높고, 6008만 있으면 Windows가 기록한 대략의 시각입니다.
   - Kernel-Power 41만 있고 BugCheck 코드가 0이면 Windows가 오류 화면을 남기지 못한 경우입니다(전원 차단, 하드웨어 멈춤, 강제 재부팅 등 여러 가능성).
   - 직전 30분 기록과 직전 센서 값(그 시각에 프로그램이 실행 중이었다면).
3. 같은 코드가 반복되는지 '반복 문제'에서 확인하고, 진단의 '원인 후보'에 적힌 **추가 검증 방법**을 따라 하나씩 확인합니다.
4. 덤프 파일 내용 분석(원인 드라이버 찾기)은 이 프로그램이 하지 않습니다. 필요하면 WinDbg 같은 전용 도구를 쓰세요.
   덤프 파일은 이 프로그램이 읽기만 하며 수정·삭제하지 않습니다. `C:\Windows\Minidump`는 보통 관리자 권한이 있어야 읽을 수 있어 "권한 부족"으로 보일 수 있습니다.

### GPU 드라이버 오류(화면 멈춤·드라이버 재설정)를 조사할 때

1. 이벤트 탐색에서 분류 'GPU 드라이버'를 고르고 '같은 문제끼리 묶어 보기'를 켭니다(Display 4101, nvlddmkm, LiveKernelEvent 141/117 등).
2. 이벤트를 골라 '전후 센서 보기'로 그 시각의 GPU 전력·온도·클럭을 봅니다. 그 시각에 프로그램이 꺼져 있었다면 센서 기록이 없습니다.
3. 드라이버를 바꾼 적이 있다면 타임라인에서 그 시점을 확인하고 비교 화면에서 전후를 비교합니다.

### BIOS 업데이트, EXPO, 메모리 전압 변경의 효과를 볼 때

1. 변경하기 **전에** 프로그램을 실행해 두면 그 시점의 구성 스냅샷과 센서 기록이 남습니다(필수는 아님).
2. 변경한 뒤 타임라인 → **변경 기록 추가**에서 종류(BIOS 업데이트/EXPO/메모리 전압 등), 날짜·시각, 제목, 바뀐 값(예: VDD 1.35 → 1.40 V)을 저장합니다.
3. 그 기록을 골라 **기준선으로 지정**합니다.
4. 며칠 사용한 뒤 비교 화면에서 그 기준선을 고르고 이전·이후 일수를 정해 **전후 비교**를 누릅니다.
5. 결과를 읽을 때:
   - 이후 기간이 짧거나 오류가 드물면 '표본이 적어 판단 어려움' 또는 '우연으로도 설명 가능한 차이'로 나옵니다. 며칠 더 기록한 뒤 다시 비교하세요.
   - **같은 기간의 다른 변경**이 있으면(예: 같은 주에 GPU 드라이버도 바꿈) 어느 변경의 영향인지 이 비교만으로 구분할 수 없습니다.
   - 사용 패턴(게임·AI 작업 시간)이 달라도 오류 빈도가 달라집니다. 센서 통계로 부하가 비슷했는지 함께 보세요.

### WHEA 하드웨어 오류가 보일 때

- 이벤트 상세의 '이벤트에서 읽은 값'에 구성 요소(판정: CPU·메모리·PCIe·알 수 없음), 오류 종류(수정됨·치명적), ErrorSource와
  MCA 뱅크·장치 ID 같은 원본 필드가 표시됩니다. 구성 요소는 이벤트 데이터·메시지·이벤트 ID로 판정하며 판정할 수 없으면 '알 수 없음'입니다.
- 수정된(Corrected) 오류가 가끔 기록되는 것만으로 고장이라고 볼 수 없습니다. 반복 횟수, 특정 변경(EXPO·전압·BIOS) 이후 증가했는지를 비교 화면으로 확인하세요.

### 일부 로그가 "권한 부족"으로 표시될 때

- 이 프로그램은 일반 사용자 권한으로 동작하며 스스로 권한을 올리지 않습니다.
- 읽으려면 관리자 권한으로 실행하거나, Windows의 **Event Log Readers** 그룹에 계정을 추가하는 방법이 있습니다(사용자가 직접 판단해 설정).
- 읽지 못한 로그는 진단 보고서의 '수집 범위와 한계'에 표시되어, 그 로그의 기록이 없다는 사실이 "문제가 없었다"로 해석되지 않게 합니다.

### 다른 사람에게 자료를 보여 줄 때

- 진단 화면의 **진단 자료 묶음** 또는 각 화면의 내보내기를 씁니다. 기본값 '개인정보 최소'는 메시지와 이벤트 데이터를 빼고, 장치 인스턴스 ID를 줄입니다.
- 상세 내보내기를 고르면 메시지가 포함됩니다. 사용자·컴퓨터 이름, 사용자 폴더 경로, SID, 이메일, 비밀값 형태는 가리지만,
  메시지에 다른 개인 정보가 있을 수 있으니 보내기 전에 파일을 확인하세요.
- 이 프로그램은 자료를 어디로도 보내지 않습니다. 공유는 사용자가 파일을 직접 전달하는 방식뿐입니다.

### 백업과 복원

- 설정 → 데이터·백업 → **백업**: 실행 중에도 일관된 복사본을 만들고 자동으로 검증합니다.
- **백업 검증**: 백업 파일이 이 프로그램의 DB인지, 손상되지 않았는지 확인합니다.
- **백업에서 복원**: 확인 후 현재 DB를 `wdl.before-restore-날짜.db`로 옆에 보관하고 백업으로 바꾼 뒤 프로그램을 다시 시작합니다. 현재 DB를 지우지 않습니다.

## 4. 명령줄 도구 `wdl`

GUI와 같은 데이터 폴더와 분석을 씁니다. 한 데이터 폴더는 한 프로그램만 쓸 수 있으므로 GUI가 실행 중이면 `wdl`은 실행되지 않습니다(종료 코드 3).

| 명령 | 내용 |
|---|---|
| `wdl status [--json]` | 수집 상태와 DB 요약. `--json`은 무결성 검사·누락 종류·복구된 실행 포함 |
| `wdl collect [--days N] [--no-snapshot]` | 한 번 수집(처음이면 과거 N일), 구성 스냅샷, 덤프 확인 |
| `wdl import --from yyyy-MM-dd [--to yyyy-MM-dd]` | 지정 기간의 과거 로그 가져오기 |
| `wdl import-xml 파일...` | `wevtutil qe System /f:xml` 출력 가져오기. 출처가 'import'로 표시되며 이 PC의 수집 위치는 바뀌지 않음 |
| `wdl report [--days N] [--out 파일.html/.md] [--detailed]` | 진단 보고서 |
| `wdl export --out 폴더 [--days N] [--detailed]` | 진단 자료 묶음 |
| `wdl compare --baseline 이름/번호 [--before N] [--after N] [--out 파일]` | 기준선 전후 비교 |
| `wdl backup --out 파일.db`, `wdl verify-backup 파일.db` | 백업, 백업 검증 |
| `wdl demo` | 가상 시나리오 추가(가상으로 표시) |
| `wdl catalog [--out 파일.md]` | 이벤트 분류 규칙 목록 |

공통 옵션: `--data-dir 폴더`, `--mock-sensors`.

## 5. 자주 묻는 질문

**업데이트 후 예전 이벤트의 분류가 바뀌었습니다.** 분류 규칙이 바뀐 버전을 처음 실행하면 이미 저장된 이벤트도 새 규칙으로 다시 분류합니다(분류·중요도·묶음·제목만 바뀌고 내용은 그대로).
묶음 기준이 바뀐 유형에 남긴 메모는 새 묶음에서 보이지 않을 수 있습니다. 가상 데이터는 다시 분류하지 않습니다.

**GPU 값이 모두 N/A입니다.** NVIDIA 드라이버가 없거나 `nvml.dll`을 읽지 못한 경우입니다. 하드웨어 화면의 센서 지원 현황에 이유가 표시됩니다. 값을 추정해서 채우지 않습니다.

**CPU 온도가 없습니다.** Ryzen CPU 온도는 커널 드라이버와 관리자 권한이 필요해 이 버전에서는 수집하지 않습니다.

**"이미 실행 중"이라며 시작되지 않습니다.** 같은 데이터 폴더를 쓰는 이 프로그램이나 `wdl`이 실행 중입니다. 알림 영역(트레이)과 작업 관리자를 확인하세요.
데이터 폴더의 `wdl.lock` 파일은 실행 중인 프로그램이 잡고 있는 표시이며, 프로그램이 강제 종료되어도 Windows가 자동으로 풀어 줍니다.

**PC 시계를 바꿨더니 타임라인이 이상합니다.** 시스템 시각 변경(Kernel-General 1)은 이벤트로 기록되고, 프로그램 실행 중의 시계 점프는 '수집 누락·제한'에 기록됩니다.
그 전후의 시간 순서는 기록된 시각 기준이므로 해석에 주의하세요.

**이벤트 로그가 지워졌다고 나옵니다.** 로그 지움 이벤트(Eventlog 104)나 레코드 번호가 처음부터 다시 시작된 것을 감지한 경우입니다. 지워진 기간의 기록은 되살릴 수 없으며 그 사실이 '수집 누락'으로 남습니다.

**데이터가 커졌습니다.** 설정 → 데이터 보존에서 센서 보존 기간을 줄이고 '보존 정책 지금 적용'을 누르세요. 이벤트는 기본 무기한 보존입니다.
